## 2. 기준선: CPU 실시간 측정 (`main` 방식)

### 2.1 측정 방법

```bash
python src/person_mask.py --source picamera --imgsz 320 --no-show --stream 8000 \
    --log runs/session2.csv --save runs/session2.mp4
python tools/analyze_log.py runs/session2.csv --plot runs/session2.png
```

- 프레임마다 아래 항목을 CSV에 기록했다.
  - 카메라 센서 촬영 시각
  - 단계별 처리 시간
  - 검출된 사람 수, 신뢰도, 마스크 면적
  - 화면 움직임
  - CPU 사용률, 온도, 클럭, 스로틀 여부
- 문제를 세 가지로 나눠 판정했다.
  - **[A] 간격:** 카메라가 찍었지만 처리하지 못해 건너뛴 프레임. 화면에 나가지 않으므로 노출은 아니다.
  - **[B] CPU:** 단계별 처리 시간, 발열, 전원 상태.
  - **[C] 모델:** 처리는 했지만 사람을 놓친 프레임. **실제 노출이다.**
- **놓친 프레임의 정의:** 앞뒤 프레임에서는 사람이 검출됐는데 중간 **2초 이하** 동안 검출이 0명인 프레임. 정답 라벨이 없어서 추정치다.

### 2.2 측정 세션

| 세션 | 시간 | 처리 프레임 | 동작 | 녹화 |
|---|---|---|---|---|
| 0차 | 286초 | 2020장 | 자유 동작 (스트리밍 첫 확인) | 없음 |
| 1차 | 115초 | 820장 | 걷기, 빠르게 지나가기, 앉기, 고개 숙이기, 가장자리, 다가가기/멀어지기 | 없음 |
| 2차 | 68초 | 434장 | 걷기 → 앉기 → 고개 숙이기 → 가장자리 → 다가가기/멀어지기 | 있음 |

### 2.3 결과

| 항목 | 0차 | 1차 | 2차 | 목표 |
|---|---|---|---|---|
| 처리 FPS | 7.1 | 7.1 | 6.4 | 15 |
| 건너뛴 카메라 프레임 | 52.8% | 52.3% | 57.6% | 0% |
| 촬영→출력 지연 (중앙/p95) | 183 / 218ms | 183 / 215ms | 200 / 229ms | 100ms 이하 |
| 사람 검출 프레임 | 1072 | 507 | 430 | — |
| **놓친 프레임** | 94장 (8.1%) | 56장 (9.9%) | **4장 (0.9%)** | 5% 미만 → 0 |

**처리 시간 (2차, ms)**

| 단계 | 평균 | 중앙 | p95 |
|---|---|---|---|
| 카메라 대기 | 0.8 | 0.8 | 0.9 |
| 전처리 + 후처리 | 3.5 | 3.5 | 4.2 |
| **모델 추론** | **129.8** | 129.6 | 132.5 |
| 마스크 칠하기 | 6.5 | 6.7 | 7.9 |
| 저장/출력 (녹화 + 스트리밍) | 14.7 | 13.7 | 19.4 |
| **합계** | **155.1** | 154.6 | 160.7 |

- 녹화를 켜지 않은 1차의 처리 합계는 137.9ms였다. 녹화를 켜면 약 15ms가 더 걸린다.
- CPU 사용률은 평균 45~47%, 가장 바쁜 코어는 96~97%였다. **PyTorch가 4코어를 다 쓰지 못한다.**
- 최고 온도는 58°C, 클럭은 2400MHz로 유지됐고 스로틀은 없었다. 쿨러는 50°C 이상에서 1단계(약 3150RPM)로 돌았다.

**1차에서 놓친 구간** (녹화가 없어 원인은 추정)

| 시각 | 길이 | 화면 움직임 | 추정 원인 |
|---|---|---|---|
| 4.0~5.0초, 7.7~9.5초, 64.8~66.0초 | 1~2초 | 작음 | 자세 변화 (앉기, 고개 숙이기) |
| 26.6~27.0초, 54.3~55.2초, 84.1~84.5초, 104.9~105.7초 | 0.5~1초 | 큼 | 빠른 이동, 카메라에 가까이 접근 |
| 28.3~53.7초 | 25초 | 작음 | 화면 밖으로 나간 것으로 추정 (놓친 프레임 집계에서 제외) |

**2차에서 놓친 구간** (녹화 영상으로 확인)

| 시각 | 길이 | 확인 내용 |
|---|---|---|
| 40.5~41.0초 (#255~#258) | 4장 | 카메라 방향이 바뀌며 사람이 오른쪽 가장자리로 빠짐. 마스크 면적이 21% → 15% → 8% → 4% → 0으로 줄었고, **화면 끝에 남은 머리나 어깨 일부가 가려지지 않음** |

## 3. `main` vs `seok` 비교

### 3.1 비교 대상

| | `main` | `seok` |
|---|---|---|
| 브랜치 / 커밋 | `main` `e5c86b0` | `seok` `dc5b06d` |
| 실행 파일 | `src/person_mask.py` | `src/person_mask_tracking.py` |
| 사람을 못 찾은 프레임 | **원본 그대로 출력** | 버퍼에 보관한다. 다음 검출 프레임이 오면 앞뒤 사람 마스크를 짝지어(Mask IoU + 헝가리안 매칭) 시간 비율만큼 이동시켜 채운다(**TRACKED**). 짝짓기에 실패하면 **검은 보호 화면(PROTECTED)** |
| 최대 대기 | — | 3프레임 (`--max-gap 3`) |
| 마스크 생성 | 폴리곤(`masks.xy`) 채우기 | 픽셀 마스크(`retina_masks=True`) |
| 공통 | imgsz 320, conf 0.25, dilate 8, 가림 색 (40,40,40) | 같음 |

### 3.2 비교 방법

1. **같은 입력을 쓴다.** 사람의 움직임은 매번 다르므로 원본을 한 번만 녹화하고, 두 방식에 똑같이 넣었다.
2. Pi에서 각 방식으로 녹화 파일을 처리했다. 파일 입력이라 **모든 프레임을 처리**한다(실시간 건너뜀 없음).
3. 두 방식의 **출력 영상**을 프레임 단위로 원본과 맞춰, 사람이 실제로 가려졌는지 판정했다(`tools/compare_methods.py`).
   - **정답 대용:** 더 큰 기준 모델 `yolov8m-seg`(imgsz 640)가 원본에서 찾은 사람 영역
   - **가려짐 판정:** 출력 픽셀이 가림 색(40,40,40)이나 검정에 가까운지(허용 오차 22). 원본 자체가 그 색에 가까운 픽셀은 노출돼도 알아볼 수 없으므로 가려진 것으로 본다.
   - **노출 프레임:** 기준 모델이 찾은 사람 픽셀 중 가려지지 않은 비율이 **5%를 넘는** 프레임. 사람 면적이 400픽셀 미만이면 판정에서 뺐다.

```bash
# 1) 원본 녹화 (AI 없음)
python tools/record_raw.py --seconds 900 --fps 15 --out runs/compare_raw.mp4 --stream 8000
# 2) 두 방식 실행
python src/person_mask.py --source runs/compare_raw.mp4 --imgsz 320 --no-show --single --fps 0 \
    --save runs/cmp_main.mp4 --log runs/cmp_main.csv
(cd ../DONT_LOOK_ME_seok && python src/person_mask_tracking.py --source ~/DONT_LOOK_ME/runs/compare_raw.mp4 \
    --imgsz 320 --no-show --save ~/DONT_LOOK_ME/runs/cmp_seok.mp4 --log ~/DONT_LOOK_ME/runs/cmp_seok.csv)
# 3) 출력 비교 (MacBook)
python tools/compare_methods.py compare_raw.mp4 --method main=cmp_main.mp4 \
    --method seok=cmp_seok.mp4:crop_top=150 --reference yolov8m-seg.pt --dump 15 --out 결과
```

### 3.3 비교 영상

| 파일 | 내용 | 사양 |
|---|---|---|
| `compare_raw.mp4` | AI 없이 녹화한 원본 | 640×480, 15FPS, **70.5초, 1051장, 건너뛴 프레임 0장**, 노출 시간 중앙 10ms, 11MB |
| `cmp_main.mp4` | `main` 출력 (마스크만) | 640×480, 1051장 |
| `cmp_seok.mp4` | `seok` 출력 | 640×630 (위 150픽셀은 상태 표시 패널), 1051장 |

- 영상 내용: 걷기, 앉기, 고개 숙이기, 가장자리 걸치기, 다가가기/멀어지기. 녹화 중 카메라 방향도 바뀌었다.

  - 팀 PC: `창의문제해결 2026/측정영상/비교_main_vs_seok/`

### 3.5 해석

1. **이번 영상에서는 `seok`의 노출이 더 적었다.** YOLO가 3장 연속으로 놓친 장면에서 앞(#851)과 뒤(#855) 프레임 마스크로 정확히 채웠다.
2. **차이는 한 장면에서만 났다.** 두 방식의 YOLO 검출 결과는 같았고, 1051장 중 1048장은 출력도 사실상 같았다. "3장 차이"는 사건 1건에서 나온 결과라서 일반화하려면 더 측정해야 한다.
3. **`seok`은 지연을 대가로 치른다.** 보완한 프레임은 다음 검출을 기다리느라 0.3~0.6초 늦게 출력됐다. 지금 CPU 속도(약 7FPS)에서는 1장 기다릴 때마다 약 140ms가 더해진다. 처리 속도가 빨라지면 이 대가도 줄어든다(30FPS면 1장당 약 33ms).
4. **두 방식 모두 약점은 "화면 가장자리에 몸 일부만 걸친 순간"이다.** 2차 실시간 측정에서 놓친 장면(40.5초)과 샘플 이미지에서 놓친 사람도 같은 유형이다.

### 3.6 한계

- **빈 방 구간이 없었다.** `seok`은 검출이 비면 보완하거나 검은 화면을 낸다. 사람이 없는 시간이 길 때 홈캠 화면이 검게 나가는지는 이번에 확인하지 못했다.
- **파일 기반 비교라 실시간 조건과 다르다.** 실제 카메라에서는 처리가 느려 프레임의 절반 이상을 건너뛰므로, 앞뒤 프레임 간격이 더 길고 보완 난이도도 다르다.
- **기준 모델도 틀린다.** 컵을 사람으로 본 경우가 있었다. 노출 판정 이미지는 사람이 직접 확인해야 한다.
- 측정자 1명, 장소 1곳, 70초로 표본이 작다.
