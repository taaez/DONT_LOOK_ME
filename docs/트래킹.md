# 앞뒤 프레임으로 누락 마스크 보완

기존 `person_mask.py`는 그대로 두고, 버퍼 기반 실험 프로그램을 추가했다.
구현 가이드의 사람별 마스크·이동 보정·Mask IoU·헝가리안 연결 방식을 사용한다.

```bash
pip install -r requirements.txt
python src/person_mask_tracking.py --source 0
python src/person_mask_tracking.py --source picamera --fullscreen
# 1·3·5번에서 실제로 사람이 검출되는 영상으로 2·4번 누락 재현
python src/person_mask_tracking.py --source sample.mp4 --drop-frames 2,4 --save runs/tracked.mp4 --log runs/tracked.csv
```

## 동작

- 성공적으로 읽은 입력 순서에 고정 번호 1, 2, 3…을 붙인다. 카메라 읽기 오류도 진단 번호 하나를 사용한다. 하드웨어가 전달하지 않은 프레임의 번호를 추정하는 기능은 아니다.
- 2번 검출이 비면 원본을 버퍼에 보관한다. 3번 도착 후 1번과 3번 사람별 마스크 중심을 정렬하고 Mask IoU를 계산한다. 거리·IoU 기준을 통과한 쌍에 대해 미매칭을 허용하는 헝가리안 할당을 수행한다.
- 양쪽의 모든 사람이 일대일 연결될 때만 실제 관측 시각의 비율로 마스크를 양방향 이동시킨다. 이동한 두 마스크의 합집합을 팽창해 2번을 가린다. 4번도 3번·5번으로 같은 처리를 한다. 중간 추정 마스크를 실제 관측으로 재사용하지 않는다.
- 출력 순서는 1→2→3→4→5다. 정상 프레임은 즉시 출력하고 누락 구간만 다음 관측을 기다린다. 최근 출력 목록과 최근 검출 누락 번호는 큰 번호부터 표시한다. 누락 목록은 최근 16건, 출력 목록은 최근 8건이며 전체 결과는 CSV에 남긴다.
- 초록 `DETECTED`: 현재 모델 마스크 사용. 노랑 `TRACKED`: 앞뒤 마스크 보완, `anchors=1,3`처럼 근거 번호 표시. 빨강 `PROTECTED`: 검은 보호 화면.
- 앞 관측 없음, 사람 수 불일치, 연결 실패, 추론 오류, 크기 변경, 파일 끝의 미해결 구간은 보호 화면으로 출력한다. 최대 `--max-gap 3`장을 기다리며 이를 초과하면 대기 구간 전체를 보호 화면으로 내보낸다.
- CSV는 각 출력의 고정 번호, 상태, 양끝 번호, 검출 누락 여부, 관측 시각, 수신부터 출력까지 지연을 기록한다. 파일 관측 시각은 프레임 번호/FPS, 카메라는 단조 시계 기준 수신 시각이다.

## 조정 및 한계

`--min-iou 0.15`, `--max-distance 0.25`(영상 대각선 대비 이동 거리), `--dilate 8`로 연결·가림을 조정한다. `q` 또는 Ctrl+C로 종료한다. `--no-show`는 화면 없이 저장·로그를 수행한다. 출력에는 보호 처리된 영상만 포함한다.

후속 관측을 기다리므로 누락 구간에는 지연이 추가된다. 파일은 입력 한 장당 출력 한 장을 저장하며, 실시간 카메라 녹화는 처리 FPS가 낮으면 실제 시간보다 짧게 재생될 수 있다. 기존 실행기의 벽시계 반복 녹화 방식은 이 실험 프로그램에 적용하지 않았다.

이 방식은 신체 윤곽의 실제 움직임을 추정하는 실험용 보간이다. 급격한 자세 변화, 교차하는 비슷한 사람, 양끝에 없는 새 사람, 부분 미검출은 보호를 보장하지 않는다. 검출이 일부라도 있으면 정상 관측 후보가 되므로 한 사람만 놓친 경우를 항상 감지하지 못한다. 빈 검출은 빈 방과 구분할 근거가 없어 보완되지 않으면 검은 화면을 낸다. 실장치의 노출 방지 보장이 필요한 경우에는 기존 가이드의 직전 보호 영상 유지/전체 보호 화면 정책을 사용해야 한다. 추정 성공 표시는 개인정보 보호 성능 검증을 의미하지 않는다.
