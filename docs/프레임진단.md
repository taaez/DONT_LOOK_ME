# 프레임 진단 — 마스킹이 안 되는 프레임의 원인 나누기

최종 목표는 **사람이 가려지지 않은 채 출력되는 프레임 0**이다. 문제가 생기는 원인은 세 가지로 나눠서 잰다.

| 구분 | 무슨 문제인가 | 화면에 노출되나 | 측정 도구 |
|---|---|---|---|
| **[A] 간격** | 카메라가 찍었는데 처리를 못 하고 건너뛴 프레임 | **아니오**. 끊김과 지연만 생김 | `person_mask.py --log` → `analyze_log.py` |
| **[B] CPU** | 프레임 하나 처리하는 시간이 김 (추론, 발열, 전원 등). [A]의 원인이 됨 | 아니오. 끊김과 지연만 생김 | 위와 같음 |
| **[C] 모델** | 처리는 했는데 사람을 놓치거나 몸 일부만 가린 프레임 | **예. 실제 노출** | 실시간 로그로 의심 프레임을 찾고 `offline_eval.py`로 확정 |

[A]와 [B]는 영상이 부드러운지, 지연이 100ms 이하인지에 관한 문제다. 노출 0을 위해 가장 먼저 잡아야 할 것은 **[C]**다.

---

## 1단계: 기준선 측정 (AI 없이 카메라만)

```bash
python tools/record_raw.py --seconds 30 --fps 15 --out runs/raw.mp4
```
- AI 없이 카메라와 저장만 했을 때 건너뛴 프레임이 0인지 확인한다. 0이 아니면 카메라나 저장 쪽 문제다.
- 여기서 만든 `runs/raw.mp4`는 3단계에서 쓰는 테스트 영상이 된다.
- 찍는 동안 걷기, 빠르게 지나가기, 앉기, 화면 가장자리에 걸치기, 일부만 보이기 같은 어려운 상황을 일부러 넣는다.

## 2단계: 실시간 진단 (실제 장치 조건)

```bash
python src/person_mask.py --source picamera --imgsz 320 --no-show --log runs/live.csv
# 30초 이상 촬영한 뒤 Ctrl+C
python tools/analyze_log.py runs/live.csv --plot runs/live.png
```
- 프레임마다 아래 내용이 CSV로 기록된다.
  - 카메라 센서 촬영 시각
  - 단계별 처리 시간 (전처리 / 추론 / 후처리 / 마스크 / 저장·출력)
  - 검출된 사람 수, 신뢰도, 마스크 면적
  - 화면 움직임
  - CPU 사용률, 온도, 클럭, 전원·발열 제한
- 분석 결과는 [A], [B], [C]와 종합 판정으로 나뉘어 출력된다.
- 비교 실험 예:
  - `--imgsz 256/320/416`
  - `--low-latency` (카메라 큐 끄기)
  - `--fps 0` (FPS 상한 없음)
  - NCNN 모델

## 3단계: 모델 성능 확정 (PC 권장)

`runs/raw.mp4`를 PC로 다운로드한 뒤 실행한다.
```bash
python tools/offline_eval.py runs/raw.mp4 --imgsz 256,320,416,640 --conf 0.15,0.25 \
    --reference yolov8x-seg.pt --dump 20
```
- 모든 프레임을 처리하기 때문에 [A]·[B]의 영향이 없고, **순수하게 모델/설정 문제**만 남는다.
- 큰 기준 모델(`yolov8x-seg`)의 결과를 정답 대용으로 쓴다. 우리 마스크가 기준 모델이 찾은 사람 픽셀을 얼마나 못 가렸는지 보고 **노출 프레임 비율**을 계산한다.
- `--dump`로 저장한 이미지에서 빨간 부분이 가려지지 않은 영역이다. 기준 모델도 틀릴 수 있으니 눈으로 확인한다.
- 추론 시간은 PC 기준 값이다. Pi에서 걸리는 시간은 2단계에서 잰 값을 쓴다.

## 판정 기준

| 결과 | 원인 | 대응 |
|---|---|---|
| 1단계에서도 건너뜀 | 카메라나 저장 | 해상도/FPS 낮추기, 저장 끄고 비교 |
| 2단계에서 건너뜀 + 처리 시간 > 카메라 간격 + 추론 비중 큼 | CPU (모델 연산량) | imgsz↓, NCNN, AI HAT+(Hailo) |
| 처리 시간 < 카메라 간격인데 건너뜀 | 간격(타이밍) | `--fps`와 카메라 FrameRate 맞추기 |
| 시간이 지날수록 느려짐, 온도 80°C 이상, 스로틀 감지 | 발열이나 전원 | 쿨러, 공식 27W 어댑터 |
| 3단계 노출 비율이 높음 | 모델/설정 | conf↓, imgsz↑, dilate↑, 아래 보완책 |
| 3단계는 괜찮은데 2단계 [C] 의심이 많음 | 실시간 조건 (흐림, 노출 시간 등) | 노출 시간, 조명 확인 |

## 측정 결과 파일 관리
- `runs/`, `*.mp4`, `*.csv`는 git에 올라가지 않는다. 원본에 사람이 찍혀 있기 때문이다.
- 팀 내부 확인용으로만 쓰고, 끝나면 지운다.
