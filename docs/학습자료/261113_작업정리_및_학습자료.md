## 1. 프로젝트와 오늘의 목표

**DONT LOOK ME**는 기존 홈캠(Tapo, 15FPS) 렌즈 앞에 붙이는 장치다. 장치 안에서는 다음 순서로 동작한다.

```
[우리 카메라] → [AI가 사람 영역 찾기] → [사람 영역을 회색으로 칠하기] → [작은 디스플레이에 출력] → (Tapo 홈캠이 이 화면을 촬영)
```

Tapo는 원본을 보지 못하고 **사람이 가려진 화면만** 찍는다. 사람의 위치와 움직임은 보이지만, 얼굴이나 외형은 보이지 않는 것이 목표다.

**최종 목표:** 사람이 가려지지 않은 채 나가는 프레임 **0**, 우리 장치가 더하는 지연 **100ms 이하**

**오늘의 목표**
1. 이전에 남아 있던 문제 해결: 색이 뒤바뀜, 녹화 영상이 빨리 재생됨
2. "마스킹이 안 되는 프레임"이 생기는 원인을 **간격 / CPU / 모델**로 나눠 측정하는 도구 만들기
3. 실제로 측정해서 기준선 만들기
4. 팀원 브랜치(`seok`)의 보완 방식과 비교하기

## 2. 오늘 한 일 (시간 순서)

### 2.1 코드 정리와 GitHub 업로드
- 이전에는 `가중치/` 폴더 하나에 코드, 가중치, 문서가 섞여 있었다. 이것을 `src/`(코드), `weights/`(모델), `docs/`(문서), `tools/`(측정 도구)로 나눴다.
- GitHub 저장소 `taaez/DONT_LOOK_ME`에 올렸다. **원본 영상과 측정 결과(`runs/`, `*.mp4`, `*.csv`)는 `.gitignore`로 올라가지 않게** 했다. 사람 얼굴이 찍힌 원본이기 때문이다.

### 2.2 색 뒤바뀜 수정 (`BGR888` → `RGB888`)
- **증상:** 빨간 물건이 파랗게, 파란 물건이 빨갛게 보였다.
- **원인:** 아래 3.6 참고. Picamera2의 포맷 이름이 직관과 반대다.
- **확인:** 수정 후 Pi로 촬영해 커피컵의 파랑, 빨대의 노랑이 실물과 같은지 확인했다.

### 2.3 녹화 영상이 빨리 재생되는 문제 수정
- **증상:** 30초를 녹화했는데 영상이 10초쯤으로 빨리 재생됐다.
- **원인과 해결:** 아래 3.8 참고. 실제 경과 시간에 맞춰 빈 시간을 직전 프레임으로 채웠다.

### 2.4 microSD를 다시 구운 사건 (교훈)
- 지난번에는 팀원 핫스팟으로 작업했다. 이번에는 그 팀원이 없어서, 다른 노트북의 **Raspberry Pi Imager로 새 핫스팟을 넣고 "쓰기"를 눌렀다.**
- **Imager의 "쓰기"는 Wi‑Fi 설정만 바꾸는 기능이 아니다. 카드 전체를 지우고 OS를 새로 설치한다.** 그래서 이전에 설치한 환경이 모두 사라졌다.
- 코드는 GitHub에 있어서 `git clone`으로 바로 복구했다. 패키지(PyTorch 등)는 다시 설치했다.
- **교훈:**
  - Wi‑Fi만 추가하려면 Pi에서 `sudo nmcli dev wifi connect "이름" password "비번"`을 쓴다. 카드를 다시 굽지 않는다.
  - 코드는 항상 GitHub에 올려 둔다.

### 2.5 핫스팟으로 Pi에 접속하기
- 노트북과 Pi를 같은 핫스팟에 연결하고 `ssh dontlookme@dontlookme.local`로 접속했다.
  - `dontlookme`(앞): 사용자 이름
  - `dontlookme.local`(뒤): Pi의 호스트명 + `.local`
- IP 주소를 몰라도 `.local` 이름으로 찾아갈 수 있다(mDNS).
- 아이폰 핫스팟에서는 노트북이 Pi에 **IPv6로만** 연결됐다. 그래서 처음 접속할 때 이름을 찾는 데 5초쯤 걸린다.
- 비밀번호는 Imager에서 구울 때 정한 값이다. 기본 비밀번호는 없다.
- **SSH 키 등록:** `ssh-copy-id`로 노트북의 키를 Pi에 등록하면 비밀번호 없이 접속된다. Claude가 원격 명령을 실행하려면 이 설정이 필요했다.

### 2.6 Pi 환경 설치
```bash
git clone https://github.com/taaez/DONT_LOOK_ME.git && cd DONT_LOOK_ME
python3 -m venv --system-site-packages .venv
.venv/bin/pip install --no-cache-dir torch torchvision --index-url https://download.pytorch.org/whl/cpu
.venv/bin/pip install --no-cache-dir ultralytics
```
- `--system-site-packages`: OS에 설치된 `picamera2`를 가상환경 안에서도 쓰기 위한 옵션. 빼면 `picamera2`를 찾을 수 없다는 오류가 난다.
- CPU용 PyTorch를 먼저 설치: 그냥 설치하면 GPU(CUDA)용 대용량 파일을 받으려고 해서 용량 부족 오류가 날 수 있다.
- OpenCV는 ultralytics를 설치할 때 함께 설치된다. 그래서 `sudo`가 필요한 `apt install python3-opencv`를 하지 않아도 됐다.

### 2.7 카메라 초점 문제 발견 → 자동초점 켜기
- 처음 찍은 사진이 전부 뿌옇게 나왔다. 확인해 보니 렌즈 앞이 가려져 있었고, 카메라 위치를 바로잡았다.
- 그다음에 비교해 보니, Camera Module 3는 **기본값이 초점 고정**이라 거리가 다르면 흐렸다.
  - 고정 초점: 선명도 28.6
  - 연속 자동초점: 선명도 150.7
- 흐린 영상은 YOLO가 사람을 놓치는 원인이 된다. 그래서 **연속 자동초점을 기본으로 켰다**(`AfMode = Continuous`).

### 2.8 진단 도구 만들기
"마스킹이 안 되는 프레임"이라고 한마디로 부르지만, 원인은 셋으로 나뉜다(3.5 참고). 이를 나눠 재기 위해 다음을 만들었다.

- `tools/offline_eval.py`: 녹화 영상의 모든 프레임을 여러 설정으로 평가
- `tools/compare_methods.py`: 여러 방식의 출력 영상을 비교해 실제 노출을 판정

### 2.9 브라우저로 실시간 화면 보기

## 3. 핵심 개념 공부

### 3.1 YOLO 세그멘테이션
- **검출(detection):** 사람 위치를 **사각형 박스**로 알려준다.
- **세그멘테이션(segmentation):** 사람의 **윤곽(픽셀 단위 영역)** 까지 알려준다. 우리는 이 영역을 칠한다.
- `yolov8n-seg`: YOLOv8의 가장 작은(n = nano) 세그멘테이션 모델. COCO 데이터셋 80종으로 학습돼 있고, 우리는 **사람(클래스 0)만** 쓴다(`classes=[0]`).
- 주요 설정
  | 옵션 | 의미 | 바꾸면 |
  |---|---|---|
  | `imgsz` | 모델에 넣기 전에 줄이는 크기 | 작게: 빠르지만 작은 사람이나 가장자리에 걸친 사람을 놓침. 크게: 정확하지만 느림 (320 → 133ms, 640 → 471ms) |
  | `conf` | 이 신뢰도 이상만 사람으로 인정 | 낮추면: 놓치는 사람이 줄지만 오검출이 늘어남. 가리는 용도라 낮게(0.25) 시작 |

### 3.2 마스킹 과정 (`person_mask.py`)
```
YOLO 결과 → 사람마다 윤곽 폴리곤(masks.xy) → 모두 합쳐 하나의 흰색 마스크(fillPoly)
         → 경계를 8픽셀 넓힘(dilate) → 마스크 영역을 (40,40,40) 회색으로 칠함
```
- **dilate(팽창):** 윤곽이 실제 몸보다 약간 작게 나오는 경우가 많아서, 바깥으로 넓혀 삐져나오는 부분을 줄인다.
- **같은 프레임 원칙:** 프레임 N의 마스크는 프레임 N에만 칠한다. 다른 프레임 결과를 칠하면 사람이 움직였을 때 위치가 어긋나서 노출된다.
- **fail-safe:** 추론 오류나 카메라 오류가 나면 원본 대신 검은 화면을 낸다. 하지만 오류 없이 **사람을 못 찾은 경우에는 원본이 그대로 나간다.** 이것이 지금 `main` 방식의 약점이다.

### 3.3 카메라와 YOLO는 어떻게 같이 도는가
```
카메라 (별도 하드웨어, 계속 찍음) ──▶ [작은 버퍼: 최신 몇 장만 보관, 오래된 건 덮어씀]
  15FPS = 66.7ms마다 1장                          │
                                                  ▼
YOLO 반복 (CPU, 한 번에 1장):  최신 1장 꺼내기 → 추론 130ms → 칠하기 → 출력 → 다시 꺼내기
```
- 카메라와 YOLO는 **동시에** 돈다. 하지만 YOLO는 **한 장이 끝나야 다음 장을 꺼낸다.**
- YOLO가 130ms 동안 처리하는 사이 카메라는 2장을 더 찍는다. 이 2장은 **버려진다.**
- **찍은 프레임을 전부 쌓아 두지 않는 이유:** 초당 15장이 들어오는데 7장만 처리하면 1초마다 8장씩 밀린다. 1분이면 1분 전 화면을 보여 주게 된다.

### 3.4 FPS(처리량)와 지연(latency)의 차이
- **FPS:** 1초에 몇 장을 내보내는가 (부드러움)
- **지연:** 어떤 장면이 찍힌 뒤 화면에 나오기까지 걸린 시간 (반응 속도)
- 지금 상태의 예
  - 카메라에서 기다린 시간 약 44ms + 처리 약 140~155ms = **약 200ms 지연**
  - 처리 FPS = 1000 / 140 ≈ **7FPS**
- 단계를 동시에 돌리는 구조(파이프라인)로 바꾸면 **FPS는 올릴 수 있다.** 하지만 지연은 단계를 더한 값이라 **각 단계 자체가 빨라져야** 줄어든다.

### 3.5 "프레임 유실"과 "노출"은 다르다 ([A] [B] [C])
| 구분 | 무슨 일인가 | 화면에 노출되나 | 원인 |
|---|---|---|---|
| **[A] 간격** | 카메라가 찍었는데 처리하지 못하고 건너뜀 | **아니오.** 화면에 아예 안 나감. 끊김과 지연만 생김 | 처리가 느림, 또는 타이밍이 어긋남 |
| **[B] CPU** | 한 장 처리가 느림 | 아니오. [A]를 일으킴 | 모델 추론, 발열, 전원 |
| **[C] 모델** | 처리는 했는데 사람을 못 찾음 | **예. 원본이 그대로 나감** | 모델 성능, 화면 가장자리, 흐림, 어두움 |

**노출 0을 위해 잡아야 하는 것은 [C]다.** [A]와 [B]는 지연 100ms 목표와 부드러움에 관한 문제다.

### 3.6 픽셀 포맷: BGR과 RGB
- 컬러 이미지는 픽셀마다 숫자 3개(빨강, 초록, 파랑)를 가진다. **OpenCV는 [파랑, 초록, 빨강] 순서(BGR)** 를 쓴다.
- Picamera2에서 `"RGB888"`을 요청하면 배열이 [B, G, R] 순서로 나온다. `"BGR888"`을 요청하면 [R, G, B]로 나온다. 이름과 실제 순서가 반대인데, 리눅스 픽셀 포맷의 명명 규칙 때문이다(Picamera2 공식 매뉴얼 "Image Formats" 참고).
- 그래서 `BGR888`을 쓰면 OpenCV 기준으로 빨강과 파랑이 뒤바뀐다. 회색, 흰색, 초록은 거의 그대로라서 "일부 색만 이상하다"고 보였다.
- **주의:** `RGB888`로 바꾼 상태에서 `cvtColor`로 또 바꾸면 다시 뒤바뀐다. 둘 중 하나만 써야 한다.

### 3.7 노출 시간, FPS, 자동초점
- **노출 시간:** 센서가 빛을 모으는 시간. 길면 밝지만 움직이는 사람이 흐려진다.
- **FPS가 높을수록 노출 시간의 상한이 짧아진다.**
  - 15FPS: 최대 66ms
  - 120FPS: 최대 8.3ms
  - 그래서 FPS를 높이면 어두운 곳에서 화면이 어둡고 거칠어진다.
- **자동초점:** Camera Module 3는 렌즈를 움직여 초점을 맞출 수 있다. 하지만 Picamera2 기본값은 고정이라 우리가 연속 모드로 켰다.

### 3.8 녹화 FPS 문제 (`VideoWriter`)
- mp4 파일에는 "초당 몇 장으로 재생할지"(예: 15FPS)가 고정으로 저장된다.
- 실제로는 초당 5장만 처리해서 1장씩 기록하면, 30초 동안 150장이 저장된다. 이걸 15FPS로 재생하면 **10초짜리 영상**(3배속)이 된다.
- **해결:** 프레임을 기록할 때 "지금까지의 실제 경과 시간 × 15장"이 되도록 직전 프레임을 반복 기록해 채운다(`write_until` 함수). 영상 길이가 실제 시간과 같아진다.

### 3.9 정답 없이 노출을 재는 방법 (기준 모델 비교)
- 사람이 모든 프레임에 정답을 그리기는 어렵다. 그래서 **더 크고 정확한 모델(`yolov8m-seg`, imgsz 640)** 의 결과를 정답 대신 쓴다.
- **노출률** = 기준 모델이 찾은 사람 픽셀 중, 출력 화면에서 가려지지 않은 픽셀의 비율
- 노출률이 5%를 넘으면 그 프레임을 "노출 프레임"으로 센다.
- **한계:** 기준 모델도 틀린다. 오늘도 플라스틱 컵을 사람으로 본 경우가 있었다. 그래서 노출 프레임 이미지를 **사람이 직접 확인**해야 한다.

### 3.10 `seok` 방식(앞뒤 프레임 보완)의 원리
```
프레임 1: 검출 O ─┐
프레임 2: 검출 X  │ ← 버퍼에 보관하고 기다림
프레임 3: 검출 O ─┘ → 1과 3의 사람 마스크를 짝지음
                    → 2의 시각 비율만큼 마스크를 이동시켜 2를 칠함 (TRACKED)
                    → 짝짓기에 실패하면 2는 검은 화면 (PROTECTED)
```
- **짝짓기:** 두 프레임의 사람 마스크가 얼마나 겹치는지(Mask IoU)와 중심 거리로 비용을 계산한다. 그다음 **헝가리안 알고리즘**으로 사람끼리 1:1로 짝짓는다.
- **장점:** YOLO가 잠깐 놓친 프레임도 가린다. 오늘 비교에서 `main`이 노출한 3장을 모두 막았다.
- **대가:**
  1. 다음 검출을 기다려야 해서 **보완한 프레임이 늦게 나간다** (오늘 0.3~0.6초).
  2. 사람이 없을 때도 검출이 비면 보완하거나 **검은 화면**을 낸다(빈 방 장면은 아직 확인 못 함).
  3. 대기 한도가 **프레임 수 기준(3장)** 이라, FPS가 오르면 같은 시간을 놓쳐도 한도를 넘기 쉽다.

### 4.1 `person_mask.py`의 흐름 (`main()` 함수)
```
1. 옵션 읽기 → 모델 불러오기 → 빈 이미지로 한 번 미리 추론(예열, 첫 추론이 수백 ms라서)
2. 카메라 열기 (camera.open_source) / 스트리밍 서버 시작 / 진단 로그 파일 열기
3. 반복:
   a. cap.read()            → 프레임 + 카메라 메타데이터(촬영 시각 등)
   b. process(frame)        → model.predict → mask_people (칠하기) + 진단 정보
   c. side_by_side          → 원본 | 마스크 분할 화면 (--single이면 마스크만)
   d. 녹화(write_until로 실제 시간 맞추기) / 스트리밍 / 화면 출력
   e. FPS 상한 대기 (--fps)
   f. 진단 로그 한 줄 기록 (--log)
4. Ctrl+C 또는 kill(SIGTERM) → 파일을 정리하고 실행 요약 출력
```

## 7. 자주 겪는 문제와 해결

| 증상 | 원인 | 해결 |
|---|---|---|
| Imager로 Wi‑Fi만 바꾸려다 카드가 초기화됨 | Imager "쓰기"는 OS 전체를 새로 설치함 | Wi‑Fi 추가는 Pi에서 `nmcli` 사용. 코드는 GitHub에 보관 |
| SSH `Permission denied` | 비밀번호나 **사용자 이름**이 틀림 | Imager에서 정한 사용자 이름과 비밀번호 확인 |
| SSH `REMOTE HOST IDENTIFICATION HAS CHANGED` | 카드를 다시 구워 Pi의 키가 바뀜 | `ssh-keygen -R dontlookme.local` 후 다시 접속 |
| `172.20.10.x`로는 접속이 안 되는데 `.local`은 됨 | 아이폰 핫스팟에서 IPv6로만 연결됨 | `dontlookme.local` 이름으로 접속 |
| `externally-managed-environment` | OS Python에 pip 설치가 금지됨 | venv 사용 |
| `No space left on device` (pip) | 임시 폴더와 캐시 부족 | `TMPDIR=~/pip-temp`, `--no-cache-dir`, CPU용 torch 먼저 설치 |
| `ModuleNotFoundError: picamera2` | venv를 `--system-site-packages` 없이 만듦 | venv 다시 만들기 |
| `qt.qpa.xcb: could not connect to display` | SSH에는 화면이 없음 | `--no-show`, `--stream 8000` 사용 |
| 빨강과 파랑이 바뀜 | `BGR888` 사용 | `RGB888` (3.6) |
| 영상이 흐림 | 고정 초점 | 자동초점(기본 켜짐), 렌즈 앞 이물질과 보호 필름 확인 |
| 녹화가 빨리 재생됨 | 파일 FPS > 처리 FPS | 지금 코드는 자동으로 맞춤 (3.8) |
| QuickTime에서 mp4가 안 열림 | `mp4v` 코덱 | VLC 사용, 또는 `ffmpeg -i in.mp4 -c:v libx264 -pix_fmt yuv420p out.mp4` |
| 백그라운드 실행을 끄려고 `pkill`했더니 SSH가 끊김 | 검색 패턴이 명령을 실행한 셸 자신과 일치함 | `pkill -TERM -f "[p]ython.*person_mask"`처럼 `[p]`를 넣음 |
| 쿨러가 안 도는 것 같음 | 50°C 미만이면 꺼지고, 50~60°C는 저속이라 조용함 | `cat /sys/class/hwmon/hwmon*/fan1_input`로 RPM 확인 |

## 11. 용어 정리

| 용어 | 뜻 |
|---|---|
| FPS | 초당 프레임 수 |
| 지연 (latency) | 장면이 찍힌 뒤 화면에 나오기까지 걸리는 시간 |
| 추론 (inference) | 학습된 모델에 이미지를 넣어 결과를 얻는 계산 |
| 세그멘테이션 | 물체를 픽셀 단위 영역으로 찾는 것 |
| dilate (팽창) | 마스크 경계를 바깥으로 넓히는 영상 처리 |
| imgsz | 모델 입력 크기 |
| conf | 검출 신뢰도 기준값 |
| venv | 프로젝트 전용 Python 패키지 환경 |
| SSH | 다른 컴퓨터에 원격 접속해서 명령을 실행하는 방법 |
| mDNS (`.local`) | IP 주소 대신 이름으로 같은 네트워크의 기기를 찾는 방식 |
| MJPEG 스트리밍 | JPEG 사진을 계속 보내 동영상처럼 보여 주는 방식 (`--stream`) |
| 스로틀링 | 발열이나 전원 부족 때 CPU가 스스로 속도를 낮추는 것 |
| Mask IoU | 두 마스크가 겹치는 정도 (겹친 넓이 ÷ 합친 넓이) |
| 헝가리안 알고리즘 | 두 집합을 비용이 최소가 되게 1:1로 짝짓는 방법 |
| Hailo / AI HAT+ | Pi 5에 붙이는 AI 가속 칩. 모델을 `.hef` 형식으로 변환해 실행 |
| worktree | 한 저장소에서 다른 브랜치를 별도 폴더로 동시에 꺼내 두는 git 기능 |
